# GitHub Actions

Workflows are partitioned into bootstrap CI, backend product CI, API integration tests, database/migration tests, Docker build/scan, security, release, staging/production preparation and OpenAPI validation/artifact packaging. Product jobs are visibly skipped until their required manifests/files exist, and run/fail when a package or Dockerfile exists but its required scripts/lockfile are missing. Only the bootstrap job runs in the current empty repo. Actions are SHA-pinned; build jobs use read permissions and release publication has write permission only in its publish job.

The current run proves only two bootstrap policy smoke tests. It did not run API/database tests, build or scan a container, validate an OpenAPI document, or publish an image. Release workflow attaches a commit-addressed Docker image tar, image ID and checksum after a real build; it does not publish to OCI. Durable versioned OpenAPI is attached to a backend release when a reviewed spec exists; consumer pinning remains manual. Private CodeQL/dependency review need GitHub Code Security. Production Environment approval, OIDC, registry and deployment commands are not configured. `CHANGELOG.md` is not rewritten; GitHub release notes are generated.
